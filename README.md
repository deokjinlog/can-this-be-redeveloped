# can-this-be-redeveloped

> **"이 재개발 물건, 사도 되나?"** — 재개발·재건축 물건을 살 때, 새 집(입주권)을 실제로 받을 수 있는지를 **근거와 함께** 판정한다. 예측이 아니라 **요건·자격 판정**이다.

**철학 — 판정 대신 신호+근거+확인리스트, 미확인은 미확인, 판단은 코드가.** "될 수 있나(요건·자격)"만 판정하고 "될까(실현)"는 예측하지 않는다.

## 왜 `can`(될 수 있나)이고 `will`(될까)이 아닌가
- **`can`** = 요건·자격 충족 여부 (노후도·연한·§39②/§37) → **우리가 판정하는 것.**
- **`will`** = 실제로 진행·완공될지 (조합 갈등·정치·시장) → **예측이라 우리는 안 함.**

딱 잘라 말할 수 있는 건 "요건은 충족한다(=될 수 있다)"까지. 실제로 될지는 아무도 확답 못 한다.

## 주소 한 줄이면 시작된다

```bash
python check.py "서울 관악구 신림동 10-10"
python check.py --mock "서울 관악구 신림동 10-10"     # 키 없이 흐름 확인
```

```
주소 ─addrdb─→ 법정동코드·지번(PNU)   ─parcel─→ 좌표(필지 중심)
                    ├─geo────→ 이미 정비구역 안인가 (고시도형 1,699구역)
                    ├─stage──→ 진행단계 + §39② 발동 여부   ← C게이트 첫 관문
                    ├─elapse─→ 인가 일자 → 재건축 3년 트리 자동
                    ├─gather─→ 내 건물 준공·구조·세대수 (건축물대장 API)
                    └─aging──→ 구역 경계 '안' 노후도·과소필지 (표제부 전수 × 연속지적)
                                            └─criteria_engine / engine ─→ A·C 판정
```

**API 키가 필요 없다.** 주소 해석도 좌표도 내려받은 공개 파일로 로컬에서 푼다
(juso 오픈API는 신청 화면이 고장 나 있어 못 받았는데, 결과적으로 필요가 없어졌다).
각 단계는 실패해도 나머지를 계속 진행한다 — "판단불가 N개" 대신 "이 자료만 주세요"로 수렴.

## 두 게이트 (둘 다 통과해야 새 집)
```
새 집을 받는다 = [A 이 지역이 재개발 될 수 있나] AND [C 내가 사서 입주권 자격 되나]
```

### A. 요건 모듈 — `criteria_engine.py` (✅ 5/5) + `aging.py` (✅ 10/10) + `geo.py` (✅ 11/11)
"이 지역·집이 **정비구역 지정 요건**을 충족하나" (노후도·연한).
- **이미 지정됐는지 먼저 본다**(`geo.py`): 고시도형에 있으면 지정요건은 **행정청이 이미 심사해 인정한 상태** → 우리가 다시 추정하지 않는다. A게이트 종료.
- **지역 노후도**(필수): 노후·불량건축물 비율 ≥ 서울 60%(재정비촉진 50%). ✅ 조례 검증
  → **`aging.py` 가 건축물대장 표제부 CSV 전수로 직접 계산**(아래).
- **건물 연한**: 준공 후 20~30년(조례), RC 공동주택 30년. ✅ 검증
- **선택요건**(하나 이상): 과소필지·주택접도율·노후연면적은 이제 **실측으로 계산**된다(연속지적도 결합).
  호수밀도는 '호'의 정의가 미검증이라 계산만 하고 판정엔 쓰지 않는다.

### C. 자격 모듈 — `engine.py` (✅ 6/6) + `stage.py` (✅ 10/10, "입주권 신호등")
"투기과열지구에서 사면 **조합원 지위를 승계**받나(입주권) vs **현금청산**당하나" (도시정비법 §39②·시행령 §37 13예외).
- **먼저 §39② 시점 요건부터 본다**: 재건축은 **조합설립인가 후**, 재개발은 **관리처분계획인가 후**부터 제한이 걸린다.
  그 전이면 제한 자체가 없어 13예외가 필요 없다 — 진행단계로 자동 판정(아래 `stage.py`).
- OR(13예외)·각 예외 AND, 4값(MET/NOT_MET/INSUFFICIENT/CONFLICT), 확인필요 반올림 금지, 근거등급, source_span. (`rubric.md` 참조)
- **조문은 원문에서 온다** — `law.py` 가 국가법령정보센터에서 법·시행령을 받아 `data/law.json` 에
  캐시하고, 각 예외의 근거에 그 원문을 그대로 붙인다. 미검증 조문 **0개**.

## 공통 출력 계약
- **4값**: MET / NOT_MET / INSUFFICIENT(자료 주면 해결) / CONFLICT(전문가로)
- **미검증 기준은 추측 금지** → 확인필요. 검증값만 verified=True.
- **요청자료로 수렴**: "판단불가 N개" 대신 "이 자료만 주세요."
- **3색 신호**: 될 수 있음 🟢 / 미달 🔴 / 확인필요 🟡

## 진행단계와 §39② 게이트 — `stage.py`

서울 정비사업 **1,158개소**의 진행단계(정보몽땅 게시). C게이트의 첫 관문을 서류 없이 판정한다.

```bash
python stage.py --fetch        # 목록을 직접 읽어 저장 (한 번 요청, 의존성 없음)
python stage.py --gu 관악구
python stage.py --find 신림7
python stage_test.py           # 15/15
```

원천: [정비사업 정보몽땅](https://cleanup.seoul.go.kr) 사업장검색.
페이지 파라미터는 `pageSize` 만 먹어서 한 번에 전부 받는다(엑셀다운로드는 503이 잦다).
목록에는 엑셀에 없는 게 둘 더 있다 — **조합 카페 id**(인가 일자를 읽는 입구)와
**구역 id**(`11620AGZ…`, 고시도형 `WTNNC_SN` 과 같은 포맷).

**§39② 본문의 시점 요건** — 지금까지 빠져 있던 게이트:

| 사업 | 제한이 걸리는 시점 | 그 전이면 |
|---|---|---|
| 재건축 | 조합설립인가 후 | 🔓 자유 양도 (13예외 불필요) |
| 재개발 | 관리처분계획인가 후 | 🔓 자유 양도 (13예외 불필요) |

```
신림7구역 · 재개발 · 현재 '정비구역지정'
  🔓 §39② 지위 양도 제한: 미발동 — 관리처분계획인가 전
  → 지금 시점에서는 서류 없이도 승계 가능
  ⚠ 계약~잔금 사이에 인가가 나면 결론이 뒤집힌다
```

**스코프 밖을 잘라낸다(흔한 오답)**: 가로주택·소규모재건축·소규모재개발은
「빈집 및 소규모주택 정비 특례법」, 지역주택·리모델링은 주택법이라 §39② 대상이 아니다 → `해당없음`.

**매칭은 틀리느니 비운다**: 고시도형 구역 ↔ 정보몽땅 사업장은 ① 구역 안 필지에 대표지번이 드는지
② 이름 토큰(`신림7`·`봉천4-1-2`)이 맞는지로 잇는다. 양쪽에 번호가 있는데 어긋나면 **붙이지 않는다**
— 대표지번에 부번이 없어 본번으로 넓히면 인접 구역이 걸려 `봉천3 → 봉천4-1-2` 같은 오매칭이 난다.
관악구 실측: 33구역 중 19건 매칭 · **오매칭 0** · 나머지는 미상.

**위치로 못 찾으면 이름으로 붙이지 않는다** — 구역 안 필지를 찾을 수 있었는데 대표지번이
하나도 들어오지 않았다면, 그건 "대응하는 현행 사업장이 없다"는 뜻이다. 여기서 이름 토큰으로
fallback 하면 **다른 땅의 같은 번호 구역**에 매달린다(신림1구역 2007 준공 → 신림1재정비촉진구역 조합).
관악구 실측: 오매칭을 걷어내니 매칭 20→11건으로 줄었지만, **교차검증 어긋남이 8→0**이 됐다.

**'자료 없음'을 '없음'으로 읽지 않는다** — 구역이 가진 표제부 CSV 의 법정동 밖이면 건물이
0동으로 잡히는데, 이건 철거가 아니라 자료가 없는 것이다. 사업 단계 신호를 내지 않고 그 사실을 표시한다
(관악구 33구역 중 15곳이 여기 해당 — 봉천동 CSV 가 없어서).

**매칭 신뢰도를 숨기지 않는다**: 구역 id 가 같아도 구역이 쪼개졌으면 이름이 어긋난다
(`봉천6구역` ↔ `봉천6-1구역`). 서울 실측 144건 중 130건은 이름도 일치, 14건은 분할·개명.
그래서 이름·위치를 먼저 보고 구역 id 는 최후 수단으로 쓰며, 어긋나면 `match_note` 가 경고를 단다.

**모르는 단계는 순서에 끼워넣지 않는다**: `사업시행자지정`(공공시행·신탁방식)은 조합이 없어서
§39② 의 '조합설립인가' 에 대응하는지가 불확실하다 → 순서에 넣지 않고 **확인필요**로 흘린다.

## 조문 원문 대조 — `law.py`

기준은 전부 조문에서 오는데, 지금까지 조문은 '기억'으로 인용돼 있었다. 원문을 받아 대조하니
**실제 오류가 여러 개 나왔다.**

```bash
python law.py --fetch        # 도시정비법·시행령 → data/law.json
python law.py --show 39      # 법률 제39조
python law.py --show 시행령37
```

| 대조 전 | 원문 확인 후 |
|---|---|
| 3년 트리를 `시행령 §37②` 로 인용 | **§37③1~3호**가 맞다 (§37②는 공공재개발 상가 임대) |
| 준공지연(3호)을 **재건축 전용**으로 처리 | 조문은 "재개발사업·재건축사업의 **토지**" — 재개발도 해당 |
| 장기보유(§39②4호) = 소유10·거주5 | 본문에 **"1세대 1주택자로서"** 가 붙는다 — 기간만 채워선 안 됨 |
| 경매·공매면 예외 | "**국가·지자체·금융기관**에 대한 채무를 이행하지 못하여" 로 한정 |
| §37③ 을 '불가피 사유' 하나로 뭉뚱그림 | 7개 호 — 4호 부칙상속·5호 경매·**6호 지정 전 계약+60일 내 신고**·7호 토지거래허가 |
| §39②5호·6호 없음 | 지분형주택 공유 · 공공재개발 시행자에게 양도 |
| — | **§39② 본문 괄호**: '양수' 에서 상속·이혼은 제외 → 그 경우 제한 자체가 안 걸린다 |

그래서 예외가 8개 → **13개**가 됐고, 미검증 조문이 0이 됐다.

## 양수 시점 두 갈래 — 계약일 vs 등기일

§39② 의 '양수' 가 **계약 시점인지 등기 시점인지** 조문만으로는 확정되지 않는다
(시행령 §37③6 이 '지정 전 계약체결' 을 별도 예외로 두는 걸 보면 원칙은 등기로 읽히나
유권해석이 필요하다). 이 날짜 하나가 13예외 전부의 기산점이라, 여기가 틀리면 C모듈 전체가 틀린다.

**그래서 하나를 고르지 않고 둘 다 돌린다.** 갈리면 그 자체가 답이다.

```bash
python check.py "관악구 신림동 1656-6" --계약 2020-09-01 --등기 2020-12-01
```
```
계약일 2020-09-01 기준 → 승계가능
등기일 2020-12-01 기준 → 확인필요

⚠️ 결론이 갈립니다.
  · 계약일: 조합설립인가 2020-10-27 · 양수 2020-09-01 → 인가 전 양수(제한 없음)
  · 등기일: 조합설립인가 2020-10-27 · 양수 2020-12-01 → 인가 후 양수(제한 발동)
```

기간계산만 달라지는 게 아니라 **§39② 발동 여부 자체**가 달라진다 — 계약과 잔금 사이에
인가가 나는 경우가 실무에서 실제로 문제된다. 인가 일자를 알면 시점마다 게이트를 다시 계산하고
(`gate_at`), 모르면 판별을 보류한다(추측하지 않는다).
웹 UI 에도 계약일·등기일 칸이 있어 갈리면 그 자리에서 경고한다.

## 인가 일자 — `elapse.py`

`stage.py` 는 "지금 어느 단계인가"까지만 안다. 재건축 3년 트리(예외5~7)는 **날짜**가 있어야 돈다.
조합 카페의 '추진경과' 화면에 단계별 일자가 공개돼 있어 그걸 읽는다.

```bash
python elapse.py --gu 관악구      # 자치구 단위 수집 (요청 간격 0.8s)
python elapse.py --cafe sinlim3
python elapse.py --show 미성
```

```
미성아파트 재건축정비사업 조합
  · 조합설립인가일    2020-10-27
  · 사업시행계획인가일  2025-02-27
```

이게 들어오면 **서류 없이도 3년 트리가 돌아간다**:

```
🔴 재건축: 조합설립+3년 내 사업시행인가 미신청 — 조합설립 2020-10-27, 후속 2025-02-27
🔴 재건축: 사업시행인가+3년 내 미착공 — 2025-02-27 → 1.5년 (3년 미경과, 2028-02-27 이후 재검토)
🟡 재건축: 착공+3년 내 미준공 — 착공 이력 필요
```

**3년이 안 지났으면 '확인필요'가 아니라 불성립이다.** 예전에는 후속행위 자료를 요청했는데,
기산점부터 3년이 안 지났으면 후속행위와 무관하게 예외가 성립하지 않는다 → 필요 없는 자료를 묻지 않는다.

**한계**: 근거등급 S1(관보 고시 원문 아님). (변경)인가가 여러 번이면 **최초 인가일**을 기산점으로 본다.
추진경과를 공개하지 않은 조합도 있다 — 관악구 36곳 중 20곳만 읽혔고, 없으면 없는 대로 둔다.

## 정비구역 경계 — `geo.py`

서울 고시도형 **1,699구역**(재개발 1,180 / 재건축 272 / 주거환경 132 / 촉진지구 96)을 실어
"이 주소가 이미 정비구역 안인가"를 답한다.

```bash
python geo.py --fetch                     # 원천 zip 자동 다운로드 → 변환까지 한 번에
python geo.py --search 신림                # 구역명 검색
python geo.py --at 37.49020 126.94948     # 이 좌표가 어느 구역 안인가
python geo.py --sigungu 11620             # 자치구별 목록
python geo.py --geojson out.geojson       # 지도용 WGS84 내보내기
python geo_test.py                        # 11/11
```

원천: [서울시 의제처리구역 위치정보](https://data.seoul.go.kr/dataList/OA-20957/F/1/datasetView.do) (OA-20957, 반기 갱신).
`--fetch` 가 포털에서 최신본을 받아 변환하므로 수동 다운로드는 필요 없다.

**의존성 없이 직접 구현** — SHP/DBF 파서, 횡메르카토르 투영, 데이텀 변환, point-in-polygon 전부 표준 라이브러리.
좌표계는 EPSG:2097(Bessel 1841 중부원점)이고, 폴리곤은 TM 그대로 두고 **질의 좌표만 TM으로 넣어** 비교한다(싸고 정확). 왕복 오차 5mm.

**세대를 가른다** — 고시도형은 이력을 함께 담고 있어 같은 땅에 옛 구역과 현행 구역이 겹친다.
고시번호에 박힌 고시일자(`11620NTC20241014…` → 2024-10-14)를 뽑아, **상호 포함 + 면적비 0.7~1.43**
일 때만 보수적으로 "더 최근 고시가 덮었다"고 표시한다(서울 78건). 판정은 현행 구역을 우선한다.

```
신림재정비촉진지구2구역주택재개발  2009-01-08  ⚪ 과거 세대
신림2재정비촉진구역               2025-07-11  🟢 현행
```

**지정되면 판정이 바뀐다** — 이게 이 모듈의 핵심:

```
지정 전:  🟡 확인 필요 — 노후도·면적·선택요건 자료 4건 요청
지정 후:  🟢 이미 정비구역으로 지정됨 — 요청자료 1건 (내 건물 준공일뿐)
          면적 263,578㎡ (고시도형 실측, P1) · 고시번호 11000NTC200301093702
```

지정 = 요건 충족을 행정청이 인정한 것이므로 노후도를 다시 세지 않는다. 대신 두 한계를 항상 함께 찍는다:
- ⚠ 현행 도형이라 **해제·변경 이력은 확인 불가** → 정보몽땅·자치구 고시 확인 필요
- ⚠ 지정 = A게이트 통과일 뿐, **사업이 진행·완공될지는 예측하지 않는다**

또한 재건축 구역이면 사업유형이 자동 전환되고(→ 노후도 요건 N/A, 안전진단 트리로), 촉진지구와 겹치면 노후도 기준이 50%로 내려간다.

## 필지 — `parcel.py`

연속지적도(관악구 45,070필지)가 세 가지를 동시에 푼다.

```bash
python parcel.py --setup             # data/raw/jijeok/*.shp → data/parcels-<코드>.json
python parcel.py --zone 신림7
python parcel.py --pnu 1162010200100100010

```

원천: [브이월드](https://www.vworld.kr) → 연속지적도 → 시군구. `data/raw/jijeok/` 에 풀면 된다.

| 푸는 것 | 어떻게 |
|---|---|
| **구역 경계 안 건물만 집계** | 필지 중심점이 구역 폴리곤 안 → 그 PNU 의 대장 건물 → **대리지표 딱지 제거** |
| **대지면적 결측 메우기** | 신림동 결측 6,196지번 중 **99.7%** 를 지적도 면적으로 |
| **주소 → 좌표** | 필지 중심점 (juso 좌표API 대체) |
| **주택접도율** | 지목 '도' 필지 경계를 격자에 찍어 인접 판정 → 폭 4m 도로에 4m 이상 접한 건물 비율 |

**PNU 매칭률 99.8%** (표제부 16,852지번 중 16,818).
**경계 추출 자기점검**: 필지면적 합 / 고시면적 = 신림7 99.9%, 봉천3 99.9%. 관악구 40구역 중 32곳이 90~110%.

**면적 밴드는 눈대중이 아니라 실측이다.** 연속지적도는 참고도형이라 공부면적과 다른데,
대장과 비교할 때 **외필지수로 두 집단을 갈라야 한다** — 안 가르면 밴드가 두 배로 부풀려진다:

```
외필지 0 (단일 필지, 9,664건)  도형/대장 중앙 1.003 · 90%구간 0.960~1.115  ← 진짜 도형 오차
외필지 1+ (여러 필지, 975건)   중앙 0.509                                 ← 오차 아니라 개념 차이
                               (대장 '대지면적'=건축 대지=필지 여러 개 합)
```

→ 실제 면적 추정 구간 = 도형 × [0.897, 1.042]. 90㎡ 를 걸치면 과소필지 판정을 **확정하지 않는다.**

### 주택접도율

지목이 `도`인 필지(관악구 6,546개)를 도로로 보고, 경계를 0.2m 간격으로 샘플링해 1m 격자에 스냅한 뒤
대지 필지와 겹치는 길이를 센다. 도로 폭은 폴리곤에서 `2×면적/둘레` 로 추정한다.

```
신림1재정비촉진구역  5.9%   ← 도로 195개 중 폭 4m 이상은 7개, 폭 중앙 1.8m (산동네)
신림7 재개발구역    60.9%   ← 큰길가 필지가 많음
```

**한계를 값에 붙인다**: 지목 기준이라 사도·통행로 같은 **현황도로가 빠진다** → 실제보다 낮게,
즉 *요건에 유리하게* 나올 수 있다. 그래서 기준선(40%) **±5%p 안이면 Fact 를 발급하지 않는다**
— 유리한 쪽으로 반올림하지 않는다는 규율. juso 도로 도형(신청 승인 대기)이 들어오면 딱지를 뗀다.
분모는 조례대로 **건축물**이라, 철거가 끝난 구역은 접도율을 내지 않는다.

## 노후도 전수집계 — `aging.py`

정보몽땅 게시치(S1)를 받아쓰는 대신, **건축물대장 표제부 CSV 전수**(P1)로 노후도를 직접 센다.

```bash
python aging.py                                   # 법정동 전체 요약
python aging.py --by road --top 15                # 길(도로) 단위 노후율 랭킹
python aging.py --by road --find 양지6길 --sens     # 그 길 상세 + 경과연수 기준 감도
python aging.py --by road --find 양지6길 --judge --area 23000   # 요건모듈 A 로 판정까지
python aging.py --json data/aging-sinlim.json     # 웹/서버용 집계본
python aging_test.py                              # 10/10
```

CSV 는 [건축HUB](https://open.eais.go.kr) → 건축물대장 → **표제부** 로 받아 프로젝트 폴더에 두면 자동 인식(용량 커서 gitignore).

**핵심 규율 — 준공일 미상은 반올림하지 않는다.**
노후도를 단일값이 아니라 `[하한, 상한]` 구간으로 낸다.

| | 뜻 |
|---|---|
| 하한 | 미상을 **전부 양호**로 본 값 (`노후/전체`) |
| 상한 | 미상을 **전부 노후**로 본 값 (`(노후+미상)/전체`) |
| 하한 ≥ 60% | 🟢 MET 확정 |
| 상한 < 60% | 🔴 NOT_MET 확정 |
| 구간이 60%를 걸침 | 🟡 확인필요 — **Fact 를 발급하지 않는다** |

경과연수 기준도 조례마다 20~30년이라 `--sens` 로 감도를 병기한다(검증된 `표준30` 만 판정에 사용, `완화20`·`구조혼합`은 미검증 표시).

**측정 단위 한계 — 대리지표는 결론을 확정하지 않는다.**
집계 단위는 법정동/도로/지번블록이지 **정비구역 경계가 아니다.** 값은 전수 실측이지만
**잰 범위가 요건의 그것과 다르므로** 충족도 미달도 선언하지 않고 `〔잠정 — 구역 경계 아님〕` 으로 표시한다.

```
같은 노후율 40%:
  구역 경계 기준  → 🔴 요건 미달 (확정)
  길 단위 대리지표 → 🟡 확인 필요 + "정비구역 경계 안에서 다시 집계" 요청
```

`aging.py --judge` 는 사용자가 그 범위를 구역으로 간주한 것이므로 확정 판정한다(`proxy=False`).

**구역 경계가 있으면 대리지표가 아니다** — `parcel.py` 가 들어온 뒤로는 진짜 요건값을 잰다:

```bash
python aging.py --zone 신림7 --judge
```
```
■ 정비구역 · 신림7 주택정비형 재개발사업  (주건축물 404동)
  🟢 노후·불량 동수 비율  86.9%   (기준 60%)
  · 과소필지(90㎡미만) 26.0% ~ 33.3%   [연속지적 585필지, 밴드 경계 43개]
  · 필지면적 합 77,896㎡ / 고시면적 77,935㎡ = 포착률 99.9%  ← 경계 추출 자기점검
  ✅ 집계 범위가 곧 고시된 정비구역 경계입니다 — 대리지표가 아니라 요건 그 값.
```

**사업 단계 신호** — 구역 안에 뭐가 서 있는지가 단계를 드러낸다(추정이지 확정 아님):

| 신호 | 근거 |
|---|---|
| 🧱 미착공 | 노후율 높고 필지가 잘게 쪼개져 있음 |
| 🏗 철거 완료 | 필지는 많은데 유효 대장 건물 0동 |
| 🏢 준공 완료 | 전부 신축 + 필지당 세대수 급증 (예: 19필지에 3,322세대) |

관악구 재개발 24구역이 **미착공 5 · 준공 5 · 철거 13 · 혼재 1** 로 갈렸고,
이 추정을 정보몽땅 게시 단계와 **교차검증**한다(어긋나면 숨기지 않고 표시).

실측(서울 관악구 신림동 전수, 17,622동):

```
🟢 노후·불량 동수 비율  61.6% ~ 61.9%   (기준 60%)   ← 준공일 미상 48동
   노후 연면적 비율     42.8% ~ 42.9%   (선택요건 기준 60%)
   과소필지(90㎡미만)    1.4% ~ 38.4%   ← 대지면적 미상 6,226필지 → 잠정·확인필요
```
